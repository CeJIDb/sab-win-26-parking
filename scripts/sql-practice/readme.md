# Проверка результатов SQL-заданий без публикации решений

Скрипт `verify-query-result.mjs` сравнивает CSV-результат запроса с заранее подготовленным описанием. В репозитории хранится только форма результата, количество строк и SHA-256. Эталонный SQL сохранять не нужно.

## Подготовьте описание эталонного результата

Экспортируйте результат с заголовком, фиксированным порядком строк и маркером `\N` для SQL `NULL`. Затем выполните:

```bash
npm run sql:oracle -- describe --result expected.csv
```

Команда вернет объект:

```json
{
  "columns": ["sector", "count"],
  "rowCount": 2,
  "sha256": "6e250a45a3866342beccd832c2f4528d682abd7e78c955e21fde5410c6a62fb3"
}
```

Добавьте объект в `tasks` файла `expected-results.json`:

```json
{
  "version": 1,
  "tasks": {
    "001": {
      "columns": ["sector", "count"],
      "rowCount": 2,
      "sha256": "6e250a45a3866342beccd832c2f4528d682abd7e78c955e21fde5410c6a62fb3"
    }
  }
}
```

## Проверьте результат задания

Сохраните результат пользовательского запроса в CSV с теми же правилами форматирования. Затем выполните:

```bash
npm run sql:oracle -- verify \
  --manifest sql/practice/tasks/expected-results.json \
  --task 001 \
  --result actual.csv
```

Проверка завершится ошибкой, если отличаются колонки, количество строк или SHA-256.

## Сохраняйте канонический порядок

SHA-256 учитывает порядок строк. Каждое задание должно явно задавать итоговую сортировку. CSV нормализуется к UTF-8, разделителю `,`, окончанию строк LF и одной завершающей пустой строке.

Некавыченное значение `\N` обозначает SQL `NULL`. Строковое значение `\N` должно быть заключено в двойные кавычки.
