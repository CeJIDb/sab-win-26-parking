# План: Demo Days как мини-кейсы

**Дата**: 2026-05-13
**Задача**: Привести 5 файлов `docs/demo-days/demo-N/readme.md` к единому базовому шаблону (повестка + артефакты-источники + материалы выступления + связанные документы) и добавить в корневой `README.md` витринный раздел «5 этапов / 5 demo» компактной таблицей. Подплан 5 из roadmap [plans/2026-05-12-portfolio-roadmap.md](2026-05-12-portfolio-roadmap.md).

## Зачем именно так

Сейчас 5 файлов `docs/demo-days/demo-N/readme.md` написаны в разных стилях: `demo-1`, `demo-2`, `demo-3` имеют секцию «Рекомендуемое развитие» с гипотетическими файлами, которые так и не появились; `demo-4` — с собственным «как использовать материалы»; `demo-5` — наиболее свежий и лаконичный. HR/SA-интервьюер, который зашел через ссылку из README или из `project-journey.md`, видит на каждой странице разную структуру и должен переключать читательский контекст.

Единый базовый шаблон (повестка → артефакты → материалы → связанные документы) выравнивает 5 страниц по одному навигационному паттерну: «вот что показывали, вот канонические артефакты, вот материалы выступления». Это превращает каталог `demo-days/` в серию мини-кейсов, читаемых одинаково.

Корневой `README.md` уже содержит блок «8 ключевых артефактов» и «Команда». Между ними не хватает компактного «процессного» среза — за какие 5 этапов проект прошел от AS-IS до интеграций. Витринная таблица из 5 строк (по одному demo на строку) дает этот срез, не разрастаясь в narrative; за narrative-частью читатель идет в `docs/process/project-journey.md`, где блок «Демо-дни как контрольные точки» уже есть.

Альтернатива «оставить как есть» отброшена пользователем: разнобой в `demo-N/readme.md` снижает витринность; в README нет процессного блока.

Альтернатива «полноценный кейс на каждый demo с фидбэком» отброшена: зафиксированного фидбэка от гостей/наставников в репо нет, выдумывать его — против правил CLAUDE.md. Шаблон сознательно без поля «Фидбэк».

Альтернатива «расширенный шаблон с подразделом „Фокус этапа“» отброшена: 1-строчное назначение в шапке + явная повестка эту функцию уже покрывают, лишний подраздел делает страницу длиннее без нового содержания.

## Цель

1. Все 5 файлов `docs/demo-days/demo-N/readme.md` следуют одному базовому шаблону (раздел «Шаблон demo-N/readme.md» ниже), с одинаковым порядком блоков и одинаковыми названиями секций.
2. В корневом `README.md` между разделом `## 8 ключевых артефактов` и разделом `## Команда` вставлен раздел «5 этапов / 5 demo» — компактная таблица из 5 строк с колонками: Этап / Demo / Что показывали / Ключевой артефакт.
3. Блок «Демо-дни как контрольные точки» в [docs/process/project-journey.md](../docs/process/project-journey.md) (секция «Демо-дни как контрольные точки») синтаксически согласован с новой таблицей в README (одни и те же названия этапов, ссылки рабочие), но как narrative остается на месте — короткий дубль из 1 строки на demo считается допустимым.
4. CI-проверки локально зеленые: `npm run lint:md`, `npm run lint:md-links`, `npm run ci:check`.
5. Ретро написано в `docs/process/retro/2026-05-13-demo-days-mini-cases.md` по формату [docs/process/retro/README.md](../docs/process/retro/README.md). Статус подплана 5 в roadmap [plans/2026-05-12-portfolio-roadmap.md](2026-05-12-portfolio-roadmap.md) обновлен на `[x]` со ссылкой на ретро.

## Scope

**Входит:**

- Переписывание 5 файлов: `docs/demo-days/demo-1/readme.md`, `docs/demo-days/demo-2/readme.md`, `docs/demo-days/demo-3/readme.md`, `docs/demo-days/demo-4/readme.md`, `docs/demo-days/demo-5/readme.md` по единому шаблону.
- Добавление раздела «5 этапов / 5 demo» в корневой `README.md` — между блоком «8 ключевых артефактов» и блоком «Команда».
- Сверка: названия этапов в новой таблице README и в блоке «Демо-дни как контрольные точки» в `project-journey.md` совпадают; ссылки на `demo-N/readme.md` рабочие.
- Запуск локальных проверок: `npm run lint:md`, `npm run lint:md-links`, `npm run ci:check`.
- Обновление ячейки подплана 5 в таблице roadmap [plans/2026-05-12-portfolio-roadmap.md](2026-05-12-portfolio-roadmap.md) и фазы 7 — после написания ретро.
- Ретро: `docs/process/retro/2026-05-13-demo-days-mini-cases.md`.

**Не входит:**

- Правка `docs/demo-days/demo-days-overview.md` — это регламент курса, источник истины по формату самих демо-дней, не наша зона.
- Правка `docs/demo-days/readme.md` (индекс) — он уже корректно ссылается на 5 demo-N/, новой структуры не требует.
- Правка файлов презентационных колод (`demo-N-presentation-deck.md`), сценариев (`demo-N-script.md`), индексов слайдов (`demo-N/slides/readme.md`) — их содержание не унифицируется, только ссылки из `demo-N/readme.md` остаются валидными.
- Правка `docs/process/project-journey.md` — блок «Демо-дни как контрольные точки» уже корректен и согласован по названиям этапов. Если на Фазе 6 обнаружится расхождение (формулировка этапа в README и journey разная) — задача правит только README, чтобы narrative-блок в journey остался стабильным.
- Журнал трассировки — подплан затрагивает только навигационные тексты (`demo-N/readme.md`) и витрину (`README.md`); требования, артефакты-источники, архитектурные решения не меняются. Журнал не трогаем. Это явно фиксируется в «Итоге».
- Создание гипотетических файлов из секций «Рекомендуемое развитие» в `demo-1/2/3/readme.md` (`demo-N-script.md`, `demo-N-summary.md`, `assets/`) — эти секции из шаблона удаляются как mertvyy текст: они уже два месяца не приводят к появлению файлов.
- Изменение формата отображения слайдов и презентаций — они подключаются по ссылке как сейчас.
- Корректировка `<details>`-карточек из подплана 3 в README — они не пересекаются с новым разделом «5 этапов / 5 demo».

## Правила коммитов и веток

- Ветка — общая `docs/portfolio-roadmap` (как для всего roadmap).
- Коммитит и пушит пользователь через `npm run commit:atomic` (или `:dry-run` для предпросмотра). План группировку коммитов не диктует.
- Без `git add -A` и `git add .` — добавлять файлы поштучно по имени.
- В сообщениях коммитов и в документации не использовать букву «е с точками» — проектная конвенция.

## Шаблон `demo-N/readme.md`

Единая структура. Порядок секций строго фиксирован; названия и регистр заголовков — как в шаблоне.

```markdown
# Demo N — <название этапа>

<1–2 предложения: краткое назначение демо в контексте этапа проекта>.

## Оглавление

- [Повестка](#повестка)
- [Артефакты-источники](#артефакты-источники)
- [Материалы выступления](#материалы-выступления)
- [Связанные документы](#связанные-документы)

## Повестка

Что показывали на демо (список из 3–7 пунктов, по существу). Источник — оглавление слайдов из `demo-N-presentation-deck.md` (раздел `## Слайды`). `demo-days-overview.md` — только справочно, не редактировать.

- ...
- ...

## Артефакты-источники

Канонические артефакты, на которых построено демо. Ссылки от корня репозитория или относительные от файла.

- [Название артефакта](../../artifacts/...) — 1 строка, чем артефакт полезен в контексте этого demo.
- ...

## Материалы выступления

- [Презентация Demo N](demo-N-presentation-deck.md) — markdown-версия презентации.
- [Слайды](slides/readme.md) — каталог изображений слайдов.

## Связанные документы

- [Обзор Demo Days](../demo-days-overview.md) — задает общий формат и ожидания по демо.
- [История развития проекта](../../process/project-journey.md) — показывает место demo N в общей траектории проекта.
- [Индекс Demo Days](../readme.md) — верхний каталог демонстрационных материалов.
```

Правила содержания:

- **1–2 предложения в шапке** — называют этап и роль демо в нем; без фраз «каталог нужен для…», «здесь хранятся…» — пишем по сути.
- **Повестка** — короткие пункты в инфинитивах или существительных, без «логично», «по регламенту», «по текущему составу». Источник — оглавление слайдов `demo-N-presentation-deck.md` (раздел `## Слайды`). Не выдумывать.
- **Артефакты-источники** — только ссылки на конкретные файлы, существующие в репо. Каждый артефакт сопровождается 1 строкой пользы. Перед сохранением — `test -f <path>` для каждой ссылки.
- **Материалы выступления** — реально существующие в `demo-N/` файлы. `slides/readme.md` есть во всех 5 demo — пункт «Слайды» включается всегда. Пункт «Сценарий выступления» из шаблона исключен — ссылок на `demo-N-script.md` не добавлять.
- **Связанные документы** — фиксированный список из 3 ссылок: overview, project-journey, индекс demo-days. Если для конкретного demo есть еще одна органичная ссылка (например, `architecture/readme.md` для demo-4) — допустим 4-й пункт.
- **Не использовать** секции «Назначение», «Текущее содержимое», «Рекомендуемое развитие», «Фокус демо», «Как использовать материалы», «Текущий фокус demo-N» — их функции распределены между шапкой и «Повесткой».
- **Не редактировать** `demo-days-overview.md` ни при каком расхождении с Повесткой — файл в «Не входит».

## Раздел «5 этапов / 5 demo» в корневом README

Место вставки — между разделом `## 8 ключевых артефактов` и разделом `## Команда`. Искать по тексту заголовка, не по номеру строки. Перед новым разделом и после него — по одной пустой строке.

Структура раздела:

```markdown
## 5 этапов / 5 demo

5 demo-дней соответствуют 5 этапам системного проектирования проекта. Каждое demo — контрольная точка, на которой результаты этапа выносились на показ.

| Этап                             | Demo                                      | Что показывали                                                  | Ключевой артефакт                                                                                                                  |
| -------------------------------- | ----------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 1. Исследование бизнеса AS-IS    | [Demo 1](docs/demo-days/demo-1/readme.md) | Event Storming AS-IS, BPMN, UML Class, StateChart               | [event-storming-as-is.md](docs/artifacts/as-is/event-storming-as-is.md)                                                            |
| 2. Концептуальное проектирование | [Demo 2](docs/demo-days/demo-2/readme.md) | Opportunity Canvas, Impact Map, User Story Map                  | [opportunity-canvas.md](docs/artifacts/opportunity-canvas.md)                                                                      |
| 3. Функциональное проектирование | [Demo 3](docs/demo-days/demo-3/readme.md) | ES TO-BE, Контекстная диаграмма, Use Case, FR/NFR               | [context-diagram.md](docs/artifacts/context-diagram.md)                                                                            |
| 4. Архитектура                   | [Demo 4](docs/demo-days/demo-4/readme.md) | Анализ угроз (галстук-бабочка), ES TO-BE с контекстами, C4, ERD | [es-tobe-sd-contexts.md](docs/architecture/ddd/es-tobe-sd-contexts.md)                                                             |
| 5. Проектирование интеграций     | [Demo 5](docs/demo-days/demo-5/readme.md) | DFD, Sequence, JSON/XML, требования к брокерам                  | [sequence-uc-10-2-pay-online-short-term-rental.md](docs/architecture/integration/sequence-uc-10-2-pay-online-short-term-rental.md) |

Полный narrative этапов — в [docs/process/project-journey.md](docs/process/project-journey.md).
```

Правила оформления таблицы:

- Названия этапов — согласованы с блоком «Демо-дни как контрольные точки» в `project-journey.md`.
- Ссылка на demo-N всегда ведет на `docs/demo-days/demo-N/readme.md`, не на index `docs/demo-days/readme.md`.
- Колонка «Ключевой артефакт» — один артефакт-«флагман» на demo, тот же, что выбран в roadmap-таблице highlights (строки 142–149 roadmap).
- Длина каждой строки таблицы — без жесткого ограничения (Prettier-форматтер выровняет столбцы), но содержательно — не больше 2 пунктов в колонке «Что показывали».
- Не использовать букву «е с точками».
- После сохранения README запустится `format-on-write.mjs` (Prettier) — визуально проверить, что таблица осталась читаемой после авто-выравнивания.
