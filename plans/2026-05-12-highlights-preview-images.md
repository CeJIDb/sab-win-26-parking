# План: превью-картинки highlights

**Дата**: 2026-05-13
**Задача**: Подключить inline-превью к 8 highlight-блокам корневого README, используя существующие исходники из `docs/.../assets/`; для highlight без визуала (FR Бронирование) — снять TODO-метку без замены.

## Зачем именно так

В корневом README после подпланов 1 и 3 уже стоят 8 highlight-блоков с TL;DR и спойлерами «Подробнее», но каждый блок содержит TODO-метку `<!-- TODO: cover 1200×630 — подплан 2 -->`. Витрина читается, но без визуального якоря — рекрутер или интервьюер не получает мгновенного впечатления.

В то же время в `docs/.../assets/` уже лежат полноценные исходники диаграмм (JPG/PNG в исходных пропорциях), выгруженные ранее из draw.io / Miro / buildin.ai. Из 8 highlights 7 имеют прямое соответствие в существующих ассетах. Подключаем их как есть — без перегенерации в OG-формат 1200×630.

**Альтернативы отброшены:**

- _Сделать копии 1200×630 в `docs/assets/highlights/`._ Требует ручной обрезки/масштабирования каждой диаграммы; часть мелких надписей (компоненты C4, контексты ES) после ресайза станет нечитаемой. Сетка одинаковых тумбочек выглядит аккуратно, но ради аккуратности теряется содержательность — а у портфолио задача обратная.
- _Генерировать OG-карточки 1200×630 для соц-превью._ Это задача брендинга (подплан 4) — там и сделаем единый репо-cover для `<meta property="og:image">`. В подплане 2 это смешивать не нужно.
- _Сгенерировать декоративную карточку для FR Бронирование._ Создание нового аcсета без живого исходника = декоративная заглушка. Пользователь предпочёл оставить highlight 4 без cover, чем добавлять полу-фейковую картинку.

## Известные риски и принятые решения

1. **Размер JPG-исходников и скорость рендера на GitHub.** Файлы вроде `event-storming-as-is.jpg` могут весить до нескольких МБ; страница README будет тяжелее. Риск принят: оптимизация изображений вынесена в подплан 4 (брендинг), если станет реальной проблемой.
2. **Разные пропорции диаграмм.** У исходников нет единого аспект-рейтио — витрина не выглядит идеальной сеткой. Сознательный компромисс: содержательная читаемость диаграммы важнее визуальной симметрии (см. отброшенную альтернативу про 1200×630).
3. **Highlight 4 без cover.** Витрина асимметрична (7 с обложками, 1 без). Согласовано с пользователем на этапе постановки задачи: текстовый артефакт без живого визуала не превращаем в декоративную карточку.
4. **Расхождение «6 highlights в roadmap vs 8 в README».** Решено: база — 8 из README (фактическое состояние), roadmap-таблица highlights обновляется в Фазе 4 этого подплана. Так оба источника синхронизируются.
5. **Формат 1200×630.** Изначальная формулировка roadmap «`*-cover.png`, 1200×630» переинтерпретируется: она относилась к OG-image-сценарию (соц-превью). Для inline-превью в README такой обрезки не делаем — она нерационально дробит детальные диаграммы. OG-cover репозитория переносится в подплан 4. Фиксируется в roadmap явной правкой описания подплана 2.
6. **Изменение строк TODO в README.** Номера строк (20, 39, 58, 77, 96, 115, 134, 153) актуальны на 2026-05-13; если до старта подплана 2 кто-то правит README, номера сдвинутся. Решение: ориентироваться на якорь `<!-- TODO: cover 1200×630 — подплан 2 -->` (поиск через grep), а не на номера строк. Номера в DoD оставлены как ориентир, а не как контракт.
