# План: roadmap портфолио

**Дата**: 2026-05-12
**Задача**: Координирующий roadmap из 8 подпланов для приведения репозитория к виду портфолио. Каждый подплан — отдельный файл в plans/ со своим ретро. Все подпланы выполняются на единой ветке `docs/portfolio-roadmap`.

## Зачем именно так

Объем работ по портфолио большой, и удобнее идти 8 независимыми атомарными планами вместо одного гигантского. Каждый план = 1 PR = 1 ретро. Этот файл — точка контроля прогресса по всем 8 направлениям.

Аудитория портфолио: RU HR/рекрутер + RU SA-интервьюер. Репозиторий позиционируется как личное портфолио владельца — повествование ведется от первого лица, команда из 5 человек упоминается как рабочий контекст, но разделы про «личный вклад» отдельно не выделяются. Главный язык — русский, EN — кратким блоком внизу README.

Альтернатива «один общий план на все» отброшена: фазы получались бы слишком крупные, трудно отслеживать прогресс, риск регрессий выше, ретро по итогам — невозможное.

## Цель

1. Создана ветка `docs/portfolio-roadmap` от актуального `main` (это первое действие сессии — до правок файлов).
2. Создан этот файл-roadmap и первый рабочий подплан (план 7 — чистка следов Cursor).
3. По мере старта каждого следующего подплана создается отдельный файл `plans/2026-MM-DD-*.md`. По мере завершения — отметка `[x]` и ссылка на ретро.
4. Все правки накапливаются на ветке `docs/portfolio-roadmap`; подвветок и отдельных PR на подплан не заводим.

## Scope

**Входит:**

- Этот файл-roadmap.
- Описание состава 8 подпланов.
- Таблица прогресса с порядком выполнения.

**Не входит:**

- Содержание самих подпланов (каждый — отдельный файл, создается при старте).
- Реализация подпланов.

## Правила коммитов и веток

- **Единая ветка `docs/portfolio-roadmap`** для всего roadmap и всех 8 подпланов. Создается первым шагом сессии: `git switch main && git pull --ff-only && git switch -c docs/portfolio-roadmap`. Подвветок и отдельных PR на подплан не заводим.
- **Все коммиты и push делает пользователь** через `npm run commit:atomic` (или `:dry-run` для предпросмотра). Планы не диктуют группировку коммитов — скрипт сам распределяет накопившийся дифф по логическим коммитам. Агент только сообщает, когда дифф готов к коммиту.
- Без `git add -A`, поштучно.

## Известные риски и принятые решения

Зафиксировано по итогам ревью 2026-05-12.

1. **`ci:check` и `lint:md:legacy`.** Снят: подплан 8 больше **не** удаляет `scripts/check-markdown.mjs` и `lint:md:legacy` (это не legacy, а кастомный линтер — см. подплан 8 выше). Цепочка `ci:check` остаётся неизменной, риск ломки снят в корне.
2. **DoD «0 упоминаний cursor» физически недостижим** (само имя плана, имя ретро, путь рабочей директории `~/cursor/...`). Решено: DoD подплана 7 переформулирован как «cursor отсутствует в N конкретных файлах из зафиксированного списка», а не «grep дал 0». Правка зафиксирована в самом подплане 7.
3. **Demo Days.** Скоуп принят как есть, риск перерасхода принят осознанно.
4. **Порядок 8 → 1 риск ломки оснастки.** Решено: подплан 8 закрывается **только** после прогона `npm run ci:check` локально и зелёного GitHub Actions на ветке `docs/portfolio-roadmap` (push делает пользователь). Husky-смоук через `git push --dry-run` снят как технически невозможный (хук `pre-push` не срабатывает на dry-run).
5. **Удаление `docs/repo-context-compressed.md`.** Решение оставлено в подплане 8 без дополнительной проверки потребителей — риск принят.
6. **Netlify-сабдомен.** Так как репо позиционируется как личное портфолио владельца, переименование сабдомена идет без согласования с командой. Старые ссылки в demo-материалах и фидбэке остаются как исторический контекст.
7. **Превью-картинки.** Закрыт: картинки размещены внутри `<details>`
   каждого highlight (lazy-load, не нагружают первую отрисовку README),
   обёрнуты в ссылку на артефакт. Два самых тяжёлых JPG пожаты до < 2 МБ.
   Имя `sequence`-ассета приведено к имени артефакта. См. подплан 2 и
   ретро `docs/process/retro/2026-05-12-highlights-preview-images.md`.
8. **Ретро по самому roadmap.** Решено: ретро по этому файлу пишется отдельно, после закрытия 10-й фазы (см. DoD выше).
9. **Перенос разделов root README → docs/readme.md.** Решено: вариант A (см. формулировку подплана 1) — narrative-разделы уходят в `docs/process/project-journey.md` или новый `docs/project-overview.md`, а `docs/readme.md` остаётся чистым оглавлением документации. Дубль «С чего начать» снимается в пользу canonical в `docs/readme.md`.
10. **«Личный вклад» не выделяется.** Репо в roadmap позиционируется как личное портфолио владельца, а не командное (см. правку в «Зачем именно так» выше). Раздел про команду остаётся как рабочий контекст, отдельной секции «мой вклад» не создаётся.
11. **Реинжект `cursor` в `docs/process/project-journey.md` между подпланом 7 и подпланом 1.** Решено: (a) подплан 7 переписывает фразу «с помощью Cursor был собран прототип ui/» без названия инструмента (например, «с помощью AI-агента»); (b) подплан 1 при переносе narrative «Как развивался проект» в этот же файл **запрещён** добавлять упоминания AI-инструментов по имени. Зафиксировано в подплане 7 и в составе подплана 1 выше.
12. **Единая ветка `docs/portfolio-roadmap`.** Решено: все 8 подпланов работают на одной ветке без отдельных PR на подплан. Все коммиты и push делает пользователь через `npm run commit:atomic` — планы группировку коммитов не диктуют.
