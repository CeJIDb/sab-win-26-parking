# План: TL;DR-карточки highlights в README

**Дата**: 2026-05-12
**Задача**: К каждому из 8 highlight-блоков в корневом `README.md` добавить раскрывающийся `<details>`-спойлер «Подробнее» с полями Контекст / Решение / Связанные артефакты. Короткий 1–2-строчный TL;DR (из подплана 1) остаётся видимым в шапке блока. Шапки самих файлов артефактов и `docs/specs/` не правятся. Подплан 3 из roadmap `plans/2026-05-12-portfolio-roadmap.md`.

## Зачем именно так

Подплан 1 ввёл короткий TL;DR (1–2 строки) для каждого из 8 блоков README — этого хватает, чтобы решить «кликать или нет». Но HR/SA-интервьюер, который читает README как «портфолио в одном файле», получает мало контекста: непонятно, к какому этапу проекта относится артефакт, на чём основан и с чем связан, без перехода в сам файл.

Развёрнутый `<details>`-спойлер закрывает этот зазор: визуально README остаётся таким же коротким (спойлер свёрнут), но при необходимости одним кликом разворачивается полноценная карточка с этапом, обоснованием и тремя сквозными ссылками. Шапки самих артефактов не трогаем — артефакты остаются «инструментами для участников проекта», а внешняя витрина живёт в README.

Альтернатива «развёрнутые карточки всегда видны» отброшена: README вырастет в ~3 раза, теряется компактность входа. Альтернатива «вообще ничего не делать» отброшена пользователем: контекста в README сейчас недостаточно для портфолио.

## Цель

В корневом `README.md` каждый из 8 highlight-блоков (#1–#8) содержит:

- короткий TL;DR (из подплана 1, не трогаем),
- свёрнутый `<details>` с заголовком «Подробнее» и тремя полями (Контекст / Решение / Связанные артефакты),
- ссылку «→ Открыть артефакт» (из подплана 1, не трогаем).

Сами файлы артефактов и `docs/specs/` не правятся.

## Формат `<details>`-блока

Единый шаблон для всех 8 блоков `README.md`. Вставляется **между** короткой строкой `TL;DR: …` (которая остаётся как есть) и стрелкой `→ [Открыть артефакт](…)` (которая тоже остаётся как есть).

```markdown
<details>
<summary>Подробнее</summary>

**Контекст:** [этап проекта по journey-align, источник, на основании чего создан]

**Решение:** [ключевой результат или вывод артефакта, с конкретными числами]

**Связанные артефакты:** [ссылка1](путь), [ссылка2](путь), [ссылка3](путь)

</details>
```

Требования к форматированию:

- Пустая строка между `<summary>` и первым полем — обязательна, иначе GitHub markdown не отрендерит содержимое спойлера.
- Пустая строка между полями — для читаемости и стабильного рендера.
- Пустая строка перед `</details>` — обязательна.
- Ссылки в «Связанные артефакты» — относительные от корня репозитория (README в корне), **только на конкретные файлы, не на директории**.
- Не использовать букву «е с точками» — проектная конвенция.
- После сохранения файла `format-on-write.mjs` (Prettier) может перенести длинные ссылки на следующую строку — визуально проверить, что блок остался валидным `<details>`.
