## Зачем именно так

В [docs/artifacts/use-case/](../docs/artifacts/use-case/) сейчас сосуществуют две несовместимые структуры:

- **«Школа 8.2»** (2 файла: [uc-8-2](../docs/artifacts/use-case/uc-8-2-create-contract-legal-entity.md), [uc-10-2](../docs/artifacts/use-case/uc-10-2-pay-online-short-term-rental.md)) — компактная: `# H1` → `## Оглавление` → `## Метаданные` (таблица) → `## Предусловия` → `## Триггер` → `## Постусловие` → `## Основной поток` → `## Расширение` → `## Требования для UC-X.Y → интеграции` → `## Связанные документы`. Структура эталонов сверена `diff`-ом — расхождений нет.

- **«Старая школа»** (18 файлов) — расширенная: `## Назначение`, `## Контекст и источник`, `## Диаграмма`, `## Текстовое описание`, `## Ключевые элементы`, `## Логика артефакта`, обертка `## Детализация содержания` с H3 внутри (`### 1. Область действия`, `### 2. Акторы`, `### 3. Цель`, `### 4. Предусловия`, …, `### 8. Расширения`), плюс `## Выводы и решения`, `## Ограничения и открытые вопросы`.

«Школа 8.2» признана эталоном по решению владельца проекта. Унификация:

- убирает дублирование (Назначение/Текстовое описание/Область действия часто говорят одно и то же),
- понижает порог чтения для новых участников,
- упрощает скрипты валидации/индексации и поиск по структуре,
- делает корректным якорное содержание ТОС (сейчас часть якорей `## Детализация содержания` фактически пустые).

Альтернатива «оставить как есть» отброшена: рассинхронизация шапок уже мешает работе (см. этот тред).

## Целевой шаблон (зафиксирован)

Полностью оформляется отдельным файлом [docs/process/templates/use-case-template.md](../docs/process/templates/use-case-template.md) на Фазе 1. Ниже — каркас, который туда переедет, плюс пояснения для каждого раздела (в самом шаблоне будут как HTML-комментарии-плейсхолдеры, чтобы `lint:md-links` не спотыкался на `[...](...)` и `[список INT-*]`).

```markdown
# UC-X.Y «Название»

## Оглавление

- [Метаданные](#метаданные)
- [Предусловия](#предусловия)
- [Триггер](#триггер)
- [Постусловие](#постусловие)
- [Основной поток](#основной-поток)
- [Расширение](#расширение)
- [Требования для UC-X.Y → интеграции](#требования-для-uc-xy--интеграции)
- [Связанные документы](#связанные-документы)

## Метаданные

| Поле                 | Значение                                    |
| -------------------- | ------------------------------------------- |
| **Автор**            | <!-- автор -->                              |
| **Название**         | <!-- человекочитаемое название сценария --> |
| **Действующее лицо** | <!-- роли через запятую -->                 |

## Предусловия

- <!-- предусловие 1 -->

## Триггер

<!-- одно предложение про инициирующее событие -->

## Постусловие

- <!-- постусловие 1 -->

## Основной поток

1. <!-- шаг 1 -->

## Расширение

**Na. Заголовок ответвления**

Na1. <!-- шаг ветки -->
Na2. <!-- шаг ветки -->

## Требования для UC-X.Y → интеграции

<!-- список INT-* или строка "Внешних интеграций нет." -->

## Связанные документы

- <!-- [подпись](относительная/ссылка.md) — пояснение -->
```

**Правила плейсхолдеров в шаблоне:**

- Реальные ссылки оформляются только в примерах внутри fenced code blocks (как выше) — markdownlint их не парсит как ссылки.
- В теле шаблона (вне code-fence) плейсхолдеры — только HTML-комментарии `<!-- ... -->`. Никаких `[...](...)` и `[плейсхолдер]` вне кода.

## Риски

- **Сюрприз на роллауте после пилота.** Шаблон фиксируется после одного типа сценария — на втором типе вскрывается дыра, переделывать уже отрефакторенное. **Митигация:** пилотов три, разных по типу (uc-12.1 СКУД, uc-7.1 CRUD-бронирование, uc-8.1 договор-ФЛ); шаблон считается финальным только после согласования всех трех.
- **Битые внутренние якоря из `## Оглавление`** из-за ручной подстановки `X.Y` в `## Требования для UC-X.Y → интеграции`. **Митигация:** Фаза 8 содержит явный grep-чек соответствия номера в заголовке номеру в имени файла (см. ниже).
- **Битые входящие ссылки извне.** На 2026-05-28 — нет, но проверка обязательная. **Митигация:** Фаза 2 — `grep -rn "uc-[0-9]+-[0-9]+\.md#" docs/` с фильтром по старым slug'ам; результаты выписываются в план.
- **Потеря содержания** при удалении `## Выводы и решения`, `## Ограничения и открытые вопросы`. По Решению 1 — удаляем, но **по каждому непустому файлу** строка в journal с выжимкой; без этой строки фаза не закрыта. **Митигация:** Фаза 2 — exit-condition «выжимки подготовлены».
- **Скрытые расхождения двух эталонов.** Сверены `diff`-ом по списку H2: расхождений нет. Если по ходу обнаружится содержательное расхождение в формате таблицы «Метаданные» или паттерне «Расширений» — поднять на обсуждение, не вносить в шаблон молча.
- **Размер диффа коммитов.** Митигация: атомарные коммиты группами (пилоты — по одному; uc-7.x остатки — одним; uc-12.x остатки — одним; uc-8.x/10.x/прочее — одним; шаблон + readme — отдельным), через `npm run commit:atomic`.
