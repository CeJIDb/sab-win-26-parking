## Структура по демо дням

- [Demo 1](demo-1/readme.md) — Этап 1 «Исследование бизнеса (AS-IS)»: Event Storming AS-IS, BPMN въезда/выезда/идентификации/оплаты, UML Class доменной модели и StateChart договора.
- [Demo 2](demo-2/readme.md) — Этап 2 «Концептуальное проектирование»: цель «80% онлайн-взаимодействий», Impact Map, Opportunity Canvas, User Story Map с границей MVP.
- [Demo 3](demo-3/readme.md) — Этап 3 «Функциональное проектирование»: Event Storming TO-BE, контекстная диаграмма, реестр Use Case и CRUDL, навигационная карта, концептуальная модель с атрибутами, FR/NFR.
- [Demo 4](demo-4/readme.md) — Этап 4 «Архитектура»: анализ угроз «галстук-бабочка», ES TO-BE с bounded contexts (Core/Supporting/Generic), выбор модульного монолита, C4 на трех уровнях, нормализованная ER-модель.
- [Demo 5](demo-5/readme.md) — финальное демо по всем 5 этапам: DFD L1, Sequence UC-10.2, маппинг и JSON-контракты ЮKassa, OpenAPI UC-12.1, реестры ошибок «Оплата»/«SSO» (25 и 22 ошибок), требования к журналированию `NFR-LOG-*` и подвыбор Outbox vs Kafka/RabbitMQ из ADR-003.

## Заметки

- Презентационные материалы носят вспомогательный характер и могут дублировать каноничное содержание.
- Источником истины для аналитики остаются `docs/artifacts/` и `docs/specs/`.
- Для каждого демо дня предпочтительна структура `demo-N/` с отдельным `readme.md`, материалами выступления и каталогом `assets/` или `slides/`.
