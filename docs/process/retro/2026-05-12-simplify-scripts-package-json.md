# Ретро: упрощение scripts/ и package.json

**Дата:** 2026-05-13
**Длительность:** ~1 рабочий день (2026-05-12–13)
**Связанный план:** [plans/2026-05-12-simplify-scripts-package-json.md](../../../plans/2026-05-12-simplify-scripts-package-json.md)
**Агент:** Claude Code (смешанная сессия — агент + пользователь)

## 1. Задача

Убрать дубликаты из `scripts/` и `package.json`, сгруппировать скрипты по подкаталогам с сохранением истории, обновить все потребители новых путей — husky, GitHub Actions, claude-hooks, документация. Обязательное условие: `ci:check` и GitHub Actions зеленые до закрытия подплана.

## 2. Как решал

Фаза 1 — инвентаризация скрытых зависимостей тремя отдельными grep-проходами (npm-скрипты, CI workflows, исполняемые файлы) — дала полный список потребителей до начала правок. Это окупилось: обнаружилось 3 хардкода в claude-hooks, help-текст в `atomic-commit.mjs`, 2 строки в `ast-index.md` и 2 ссылки в `plan-validator/SKILL.md`.

Ключевая развилка — объединить фазы 7 (перемещение файлов) и 8 (обновление потребителей) в одну атомарную фазу без промежуточных коммитов. Если бы коммит с `git mv` вышел раньше обновления husky-путей, `pre-commit` упал бы с `ENOENT` при следующем коммите.

Отдельно выяснилось, что `.markdownlint.jsonc` не имел `extends` и правила шли инлайн — слияние в `.markdownlint-cli2.jsonc` прошло без потери правил. `check-markdown.mjs` решили оставить (это не legacy, а кастомный линтер), только переименовали скрипт `lint:md:legacy` → `lint:md:custom`.

## 3. Решил ли

**Да.** Все 12 фаз выполнены. `ci:check` — зеленый локально. GitHub Actions (`policy-checks`, `quality-gates`, `commitlint`) — зеленые после push. `scripts/` разбит по подкаталогам, история файлов сохранена через `git mv`. Дубликаты (`atomic-commit.sh`, `commit:atomic:sh*`, `.markdownlint.jsonc`, `.agents/`, `docs/repo-context-compressed.md`) удалены.

## 4. Эффективность

**Сработало:**

- Инвентаризация перед правками — ни один потребитель не остался с битой ссылкой.
- Объединение фаз 7+8 в одну — не было промежуточного сломанного состояния.
- Параллельное обновление всех потребителей (husky, CI, claude-hooks, документация) одним коммитом вместо цепочки — меньше точек отказа.

**Можно было лучше:**

- DoD-чеклист в подплане написан как 20 отдельных `- [ ]` пунктов, но их не отмечали в ходе работы. Для будущих подпланов лучше разделять DoD-критерии и исполняемые фазы.
- Фазы 11–12 (CI и ретро) зависят от действий пользователя (push) и не могут быть закрыты агентом сразу — это структурное ограничение, которое стоит отражать в плане явно.

## 5. Как было и как стало

**До:** `scripts/` — 13 файлов в плоском каталоге; два дублирующих bash/mjs скрипта atomic-commit; два файла конфигурации markdownlint; `.agents/`, `docs/repo-context-compressed.md` — мертвый груз; `lint:md:legacy` — вводящее в заблуждение имя.

**После:** `scripts/` — 7 подкаталогов (`lint/`, `plans/`, `build/`, `git/`, `integrations/`, `claude-hooks/`, `docs/`); дубликаты удалены; `lint:md:custom` — понятное имя; `ci:check` и husky-хуки указывают на актуальные пути.
