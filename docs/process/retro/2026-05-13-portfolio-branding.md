# Ретро: брендинг портфолио — badges, OG-image, Netlify-чеклист

**Дата:** 2026-05-13
**Длительность:** ~1 рабочий слот
**Связанный план:** [plans/2026-05-13-portfolio-branding.md](../../../plans/2026-05-13-portfolio-branding.md)
**Агент:** Claude Code, смешанная сессия (оркестратор + 3 подагента параллельно)

## 1. Задача

Добавить в README 5 shields.io-бейджей, создать каталог `docs/assets/` для будущего OG-image,
написать `docs/process/branding-checklist.md` с инструкцией по Social Preview и переименованию
Netlify-сабдомена.

## 2. Как решал

Фаза 0 (сверка) выполнена оркестратором вручную: ветка, отсутствие `docs/assets/`, Netlify-URL,
наличие `ci.yml`. Затем — Волна 1: три подагента параллельно (README, Assets, Process).
После возврата агентов — сверка git diff, исправление ошибки `ci:check` (строка с бейджами
оказалась 607 символов > 500, разбил на 5 строк — по одному бейджу).

## 3. Решил ли

Да, полностью. После первой волны агентов оставались два открытых пункта — OG-image PNG и
Netlify-переименование. Пользователь закрыл оба в этой же сессии:

- PNG `docs/assets/social-preview.png` (1200×630, 834K) положен и загружен в GitHub Settings →
  Social Preview. Заглушка в `docs/assets/readme.md` заменена на актуальную запись.
- Netlify-сайт переименован в `sab-win-26-parking.netlify.app`. Ссылки обновлены в 4 местах
  (README × 3 + project-journey.md). Документы-снимки не тронуты.

## 4. Эффективность

Параллельная Волна 1 сработала: три агента вернулись без конфликтов, суммарный дифф чистый.

Проблема с длиной строки (`check-markdown.mjs` ≤500 символов) возникла потому, что план
предписывал «5 бейджей в одну строку» — надо было сразу заложить разбивку на 5 строк
(inline-изображения в одном параграфе рендерятся так же). Внести это замечание в будущие планы
с бейджами.

## 5. Как было и как стало

**До:** `README.md` открывался H1 без визуальных маркеров; `docs/assets/` не существовал;
процедура обновления OG-image и Netlify нигде не была задокументирована.

**После:** под H1 — 5 бейджей (статус, CI, last-commit, license, demo) с актуальным
Netlify-URL; `docs/assets/social-preview.png` лежит в репо и подключен в GitHub Settings;
`docs/process/branding-checklist.md` содержит пошаговые инструкции по Social Preview и
переименованию Netlify-сабдомена для будущих итераций.
