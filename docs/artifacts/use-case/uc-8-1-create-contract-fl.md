## Метаданные

| Поле                 | Значение            |
| -------------------- | ------------------- |
| **Автор**            | Команда курса SAB   |
| **Название**         | Создать договор с ФЛ |
| **Действующее лицо** | Клиент (ФЛ)         |

## Предусловия

- Клиент зарегистрирован в системе.
- Клиент авторизован в личном кабинете (ЛК).
- Система доступна и функционирует в штатном режиме.
- В системе настроены доступные долгосрочные тарифы

## Триггер

Клиент в личном кабинете переходит в раздел оформления договора.

## Постусловие

- В системе создан договор клиента с `lifecycle_status = PENDING_ACTIVATION`.
- Попытка подписания по маршруту `CLIENT_SMS_ACCEPTANCE` завершена в состоянии `SIGNED`.
- Успешная полная оплата за период зафиксирована отдельно от состояния договора и запускает `EvaluateContractActivation`.
- Договор переходит в `ACTIVE` только после проверки подписи, полной оплаты, даты начала, срока действия и отсутствия блокировки; до этого он остается в `PENDING_ACTIVATION`.

## Основной поток

1. Система отображает раздел ЛК с выбором типа обслуживания (краткосрочное / долгосрочное).
2. Клиент выбирает вариант «Долгосрочный договор».
3. Система отображает форму оформления договора с полями:

- тип договора,
- период действия,
- тариф.

4. Клиент заполняет параметры договора:

- выбирает тариф,
- указывает дату начала,
- указывает дату окончания.

5. Система рассчитывает предварительную стоимость и отображает условия:

- сумма,
- период.

6. Клиент нажимает кнопку «Оформить».
7. Система отображает клиенту поле для введения кода из СМС.
8. Клиент получает проверочный код с помощью СМС на телефон.
9. Клиент вводит полученный код в поле для ввода проверочного кода.
10. Система фиксирует факт акцепта оферты клиентом и переводит текущую попытку подписания по маршруту `CLIENT_SMS_ACCEPTANCE` в `SIGNED`.
11. Система отображает предложение внести предоплату за период.
12. Клиент производит оплату выбранным способом:

- онлайн-оплата в ЛК,
- привязанная карта.

13. Система получает подтверждение об успешной полной оплате, фиксирует состояние платежа и запускает `EvaluateContractActivation`. Contract Service переводит договор в `ACTIVE` только при выполнении всех условий активации; иначе договор остается в `PENDING_ACTIVATION`.
14. Система отображает раздел привязки транспортных средств к договору.
15. Клиент выбирает ТС из профиля и подтверждает привязку.
16. Система сохраняет привязку ТС к договору и завершает оформление.
17. Система отображает результат оформления: договор подписан, оплата принята, а текущее состояние активации показано отдельно.

## Расширение

**4а. Не заполнены обязательные поля**

4а1. Система обнаруживает, что одно или несколько обязательных полей формы не заполнены.  
4а2. Система подсвечивает незаполненные поля и выводит подсказку: «Заполните обязательные поля».  
4а3. Сценарий возвращается к шагу 3 основного потока.

**12а. Ошибка оплаты**

12а1. Платежный шлюз возвращает ошибку по оплате.  
12а2. Система фиксирует неуспешную попытку платежа; договор остается в `PENDING_ACTIVATION`. Система отображает сообщение: «Оплата не выполнена. Повторите попытку».  
12а3. Клиент может повторить оплату; сценарий возвращается к шагу 12.

**12б. Отмена оплаты**

12б1. Клиент отменяет оплату.  
12б2. Система фиксирует отмену платежной попытки; договор остается в `PENDING_ACTIVATION`. Система отображает сообщение: «Оплата не выполнена. Повторите попытку».  
12б3. Клиент может повторить оплату; сценарий возвращается к шагу 12.  
12б4. Если клиент не производит оплату в течение 15 минут, платежная попытка или счет получают свое финансовое состояние, договор не активируется и остается в `PENDING_ACTIVATION`; автоматический переход договора в `CANCELLED` в этом UC не выполняется.

**15а. Нет зарегистрированных ТС в профиле**

15а1. В профиле клиента нет ни одного транспортного средства.  
15а2. Система предлагает клиенту перейти к сценарию «Добавление транспортного средства (ТС) в профиль».  
15а3. После успешного добавления ТС клиент возвращается к шагу 14 основного потока.

## Требования для UC-8.1 → интеграции

UC использует доставку СМС-кода и платежный канал. Их интеграционные контракты не детализируются в этом документе; текущая синхронизация ограничена разделением попытки подписания, жизненного цикла договора и финансовых состояний.

Маршрут `CLIENT_SMS_ACCEPTANCE` является предварительным источником модели для ФЛ. Полная детализация UC-8.1, включая таймауты, интеграции и исключения, выполняется отдельно.
