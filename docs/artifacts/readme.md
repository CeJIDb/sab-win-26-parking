## Ключевые документы

- [Карточка проекта](project-charter.md) — фиксирует цель проекта, рамки и ключевые договоренности.
- [Opportunity Canvas](opportunity-canvas.md) — описывает проблемную ситуацию, ценность решения и критерии успеха.
- [Impact Map](impact-map.md) — связывает бизнес-цель с ролями, влияниями и поставками.
- [User Story Map](user-story-map.md) — раскладывает скоуп на пользовательские активности (тарифы, доступ, профиль, автопарк, бронирование, договор, оплата, операции на КПП, мощности, аналитика) для 3 групп пользователей (клиенты, сотрудники, владелец) с явной границей MVP и согласованной терминологией.
- [Контекстная диаграмма](context-diagram.md) — задает границы системы, актеров и внешние системы.
- [DFD Level 1](dfd-l1.md) — декомпозиция платформы на 20 компонентов, единое хранилище PostgreSQL и 10 внешних систем.
- [Концептуальная модель с атрибутами](conceptual-model-with-attributes.md) — 27 сущностей домена (клиент, ТС, бронирование, парковочная сессия, договор, шаблон договора, платеж, чек, тариф, ПМ, сектор, КПП, согласие, обращение, уведомление и др.) с атрибутами, справочниками и связями — мост между предметной областью и ERD.
- [Диаграмма вариантов использования](use-case/use-case-diagram.md) — показывает актеров и карту use case.
- [Реестр use case](use-case/use-case-registry.md) — каноничная таблица 137 UC в 16 функциональных группах (ознакомление с условиями, профиль, ТС, обращения, уведомления, бронирование, договоры, оплата, доступ и ПС, тариф и др.) со связкой «участник → группа → код UC → название».
- [CRUDL-матрица](use-case/crudl.md) — таблица «участник × сущность» по 21 сущности и 10 участникам (5 ролей: КлиентФЛ, КлиентЮЛ, Владелец, Управляющий, Охранник; 5 систем: система парковки, уведомлений, СКУД, платежная система, платежный терминал): операции `C/R/U/D/L` для каждой пары.
- [Карта навигации](navigation-map.md) — структура 4 контуров UI (публичный сайт, личный кабинет клиента, административный интерфейс, рабочий контур охранника КПП): дерево страниц, переходы, модальные сценарии и зафиксированные расхождения с фактическим wireframe.
- [Анализ ИБ парковки](infosec/infosec-analyze-parking.md) — фиксирует угрозы, уязвимости и меры защиты.
- [Bow-Tie риска несанкционированного доступа](infosec/bow-tie-unauthorized-access-to-system-and-data.md) — визуализирует риск и барьеры.

## Заметки

- Имена файлов приведены к стилю **kebab-case** на латинице.
- Сохраняйте относительные ссылки; при переносе файлов обновляйте ссылки в том же PR.
- ERD и связанные модели данных вынесены в [Индекс ERD](../architecture/database/erd/readme.md) как часть архитектуры данных.
- Для артефактов, которые приходят как изображение, храните `md`-описание рядом с файлом изображения и считайте каноничным документом именно `md`.
- [Скрипт нарезки изображений на тайлы](../../scripts/docs/split-image.py) — помогает делить крупные схемы для публикации в репозитории.
